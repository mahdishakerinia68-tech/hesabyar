۲) اصلاح امنیت قفل الگو
-----------------------
در openPatternSetup و removePin، اگر patternHash وجود دارد، قبل از تغییر یا حذف الگو باید الگوی فعلی یا بیومتریک تأیید شود.

منطق پیشنهادی:

async function verifyExistingLock(){
  if(data.patternHash && data.patternSalt){
    const path=await promptPatternVerification();
    return path ? await verifyPattern(path) : false;
  }
  if(data.pinHash || data.pin){
    const p=prompt("رمز فعلی را وارد کن:")||"";
    return verifyPin(p);
  }
  return true;
}

- حذف قفل الگو فقط با verifyExistingLock انجام شود.
- تغییر الگو فقط با verifyExistingLock انجام شود.
- confirm به‌تنهایی برای حذف قفل کافی نیست.
- پس از سه خطای متوالی، حداقل ۳۰ ثانیه تأخیر اعمال شود.

۴) اصلاح موجودی انبار
----------------------
موجودی فاکتور باید قبل و بعد از ویرایش به‌صورت دقیق محاسبه شود. هر آیتم فاکتور هنگام ذخیره باید Snapshot قیمت خرید داشته باشد:

{
  productId,
  desc,
  qty,
  price,
  costPriceAtSale: Number(product?.buyPrice)||0
}

در گزارش سودآوری از costPriceAtSale استفاده شود، نه قیمت فعلی محصول.

- حذف فاکتور: فقط مقدار همان فاکتور یک‌بار به موجودی برگردانده شود.
- بازیابی فاکتور: فقط مقدار همان فاکتور یک‌بار از موجودی کم شود.
- ویرایش فاکتور: ابتدا اثر نسخه قدیمی برگردانده شود، سپس اثر نسخه جدید اعمال شود.
- برای جلوگیری از منفی شدن موجودی، کمبود موجودی باید هشدار بدهد؛ Math.max(0, ...) نباید بدون ثبت هشدار باعث پنهان شدن کسری شود.

۶) رمزنگاری بکاپ

function compareUpdatedAt(a,b){
  const ta=Date.parse(a||"")||0;
  const tb=Date.parse(b||"")||0;
  return ta===tb?0:(ta>tb?1:-1);
}

۱۲) migration داده
------------------
مهاجرت داده باید نسخه‌به‌نسخه و غیرمخرب باشد:

function migrateData(input){
  let d=structuredClone(input||blankData());
  const version=Number(d.schemaVersion||1);
  if(version<2)d=migrateV1ToV2(d);
  if(version<3)d=migrateV2ToV3(d);
  if(version<4)d=migrateV3ToV4(d);
  d.schemaVersion=4;
  return d;
}

قبل از migration از داده خام یک کپی اضطراری گرفته شود. در صورت خطا، داده قبلی نباید پاک شود.
